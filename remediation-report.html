This project is a live demonstration of Broadcom Tanzu Platform's Spring Enterprise remediation capability. One deliberately-vulnerable Spring Boot app, one patched rebuild, and a single dependency-only diff between them.

01What this is

A Spring Boot application was built with 12 real, well-known CVEs baked in by pinning old dependency versions on purpose. A React dashboard renders the findings and can fire a live request at each vulnerable endpoint to prove the exposure is real. The app was then rebuilt — in a separate git worktree — against the Broadcom Spring Enterprise repository. Every CVE closed — the security fix is entirely in pom.xml.

02How the remediation works

The headline Spring CVEs are fixed by moving to the Spring Boot 2.7.33 patch line. That release is past open-source end-of-life — Maven Central does not host it. It resolves only from the Broadcom Spring Enterprise repository, which the Tanzu Platform entitlement unlocks. That single parent bump carries patched Spring Framework, Spring Security, Jackson and H2; the remaining pinned libraries are bumped to their public fixed versions.

04Proof, not just version numbers

Each dashboard card carries the exact same live request in both builds. The payload never changes — only the response does:

Vulnerable

  • Text4Shell: ${script:…} interpolated
  • SnakeYAML: !!java.util.Date instantiated
  • SpEL routing: header expression executed

Patched (replay)

  • Text4Shell: payload returned verbatim, unresolved
  • SnakeYAML: Global tag is not allowed — refused
  • SpEL routing: T(java.lang.Runtime) rejected

05Reproduce it

  1. Configure ~/.m2/settings.xml for the tanzu-maven repository and export TANZU_USER / TANZU_TOKEN (see the setup guide).
  2. Verify the entitlement: a 200 from packages.broadcom.com/artifactory/tanzu-maven/.
  3. Build and run either branch:
cd frontend && npm install && npm run build && cd ..
mvn clean package -DskipTests
java -jar target/tanzu-vuln-demo-*.jar   # http://localhost:8080
The whole story in one line: git diff main patched-enterprise -- pom.xml is the entire security fix — dependency bumps only, no application logic. (The other files on this branch just re-skin the dashboard to its remediated state and make the demo probes report cleanly; they don't affect whether the CVEs are fixed.)
